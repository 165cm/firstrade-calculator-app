## 3. 手順A：先行販売の開始（1月中旬）

### A-1. コードの変更（PRを作る）
1. `src/config/license.ts`
   - `CURRENT_EDITION` を2026年版に：`year: '2026'`、`label: '2026年版'`、`validUntil: '2027年12月'`、`price: '$25'`、`priceJpyApprox`（その時の為替で）
   - `SALES_STATUS` を `'presale'` に
   - `PURCHASE_URL` の既定値を2026年版の商品URLに
   - `RETURNING_USER_NOTICE` を先行販売中の文言に（例：「お届けしたメールのクーポンで先行購入いただけます」）
   - `UPCOMING_EDITION` の文言が先行販売中の表示に合っているか確認（`SALES_NOTICE` の presale の文）
2. `src/app/guide/filing/page.tsx` の国税庁「記載例」リンク（URLに年度 `2024` が入っている）を最新年度に差し替える
3. ガイド・FAQ・LPの「2025年版」「2026年12月」などの表記が残っていないか検索する
4. lint・型チェック・テスト・ビルド → staging で確認

### A-2. Cloud Run（本番）の環境変数
旧方式の2つを残したまま、新方式を追加する（新方式が優先される）。
```
GUMROAD_PRODUCTS=2026年版:<2026年版の商品ID>:2027-12-31,2025年版:<2025年版の商品ID>:2026-12-31
```
- 2025年版の行は残してもよい（期限切れなので認証されない）。
- お試しサイト（staging）にも同じ設定をして、先に試す。

### A-3. 動作確認（staging → 本番）
- 2026年版のライセンスキー（自分でテスト購入、または Gumroad のテスト用キー）で認証できる
- 2025年版のキーは「期限切れ」の案内になる
- エクスポート画面から、割引コード付きで購入ページに移動できる

### A-4. Gumroad
1. 2026年版の商品を Publish（公開）
2. 2025年版の購入者へメールを送信（クーポン＋アンケート）。文面は下の「メール文面」
3. 1週間後にリマインドのメール
